### Added

- A `docs/CODE-QUALITY-STANDARDS.md` synthesizing August-2026 research into exceptional Go, shell, Docker, and operator engineering plus assume-breach testing, with an honest enforced-versus-gap breakdown and an explicit overkill list. First wave of gates wired: native fuzzing of the untrusted device-output parsers (proven to run clean), the Go race detector and `govulncheck` in CI, and ShellCheck on the gate scripts. Fixed a real bug it surfaced: the operator's logger defaulted to development mode in the released binary.
- A research-backed plan for agentic AI nodes on the mesh (`docs/plans/agent-mesh-nodes.md`): an offline, retrieval-grounded, advice-only AI node reachable over LoRa when the internet is gone. It leads with the hard constraints (a ~200-byte telegram budget, a template-and-code message scheme, the model at a powered base with cheap field radios, air-gapped from all transmit and config paths, human-decides), is global by construction (region and encryption as configuration, not US assumptions), and honestly separates the real disruption-tolerant and DTN parallels from the space hype. Architecture and roadmap updated with global-by-configuration and disruption-tolerant design principles.
- The operator now reconciles modem preset and device role in addition to region and MQTT. Each new field's export path was verified to round-trip against `meshtasticd --sim` in the integration test, so an unconvergeable field cannot slip in.
- A tool-agnostic agentic layer so any coding agent (Claude Code, Codex, Copilot) or a human can drive the repo the same way: `docs/agent-playbook.md` documents the canonical commands and the layering (AGENTS.md for conventions, the playbook for commands, a future MCP server for live state, chosen over an assistant-specific skill format for portability), and `hack/check-all.sh` runs every gate in one command, gracefully skipping a group whose tooling is absent. Exposed as `make check-all`.
- Operator integration test against real firmware: a build-tagged test drives the real reconcile loop, through the CLI-backed device client, against a live `meshtasticd --sim`, reaching convergence and reporting the real node id. It runs in a CI job (a Docker sim device plus the pinned CLI) and passes locally in about 10 seconds, giving the flagship operator an "executed against real firmware" validation that the in-memory fake cannot.
- Deterministic Go quality gates in CI, per the anti-slop mandate that wired gates beat instructions: golangci-lint (shared `.golangci.yml`, standard linter set, generated files excluded) and a meaningful-coverage floor (`hack/check-coverage.sh`, 80%, excluding generated deepcopy and the thin cmd/main), both wired into the `go` workflow for the api and operator modules and exposed as Makefile targets. The coverage gate is proven to fail below threshold. Fixed the lint findings it surfaced (unchecked errors, a deprecated field).
- The `meshtastic-operator` kpt package (CRD, generated least-privilege RBAC, ServiceAccount, Deployment) plus a multi-stage Dockerfile that bundles the pinned Meshtastic CLI the operator execs and runs non-root. Renders clean through the gate, correctly keeping the CRD and ClusterRole cluster-scoped while namespacing the ServiceAccount and Deployment.
- The `meshtastic-operator` module: a non-blocking, reboot-aware reconcile loop for `MeshtasticNode`. A pure `Converge` state machine (export, diff, apply-and-reboot on drift, report RebootPending and a requeue delay, re-verify after the device returns) drives status conditions (Reachable, ConfigInSync, RebootPending, Ready). The device sits behind a `Client` interface with a deterministic in-memory fake, a CLI-backed implementation that execs the Meshtastic CLI, and a graceful "unsupported" stand-in for transports not yet built. The whole operator is unit-tested hardware-free and cluster-free using the fake device and controller-runtime's fake client (config and reconcile at 100%, controller 85%, device 83%); a `go` CI job builds, vets, and tests it.
- Phase 4 begins: the `api/` Go module with the `MeshtasticNode` CRD (`mesh.nephmesh.io/v1alpha1`). A `connection` oneof (tcp/serial/viaGateway) enforced by a CEL rule so no validating webhook is needed, open-string enums for firmware-churn tolerance, channel PSKs by `secretKeyRef` only, a `deletionPolicy` enum, and standard status conditions. Generated deepcopy and CRD manifest via pinned controller-gen; testify unit tests (hand-written logic at 100% coverage); a `go` CI workflow running build, vet, test, and a generated-artifact freshness check.
- Phase 4 operator plan (`docs/plans/phase-4-operator.md`) from August-2026 research: the CLI-via-sidecar device path with mandatory read-back verification, a non-blocking reboot-aware reconcile state machine, single-client serialization via the workqueue, server-side-apply status with `metav1.Condition`, CEL validation over webhooks, open-string enums for firmware-churn tolerance, External Secrets Operator for the GitOps secrets flow, and testcontainers plus `meshtasticd --sim` for hardware-free testing.
- Expert-panel review outcomes folded into the docs: the control-plane-is-not-in-the-field clarification and mesh autonomy (README and FAQ), PACE and DIL and EMCON framing, a defined resilience metric (message delivery ratio, time to failover, control-plane-independence) with matching validations, and threat-model additions (induced-reconfiguration via the closed loop, Sybil and default-PSK mesh join, emission and direction-finding OPSEC).
- Scope broadened to radio systems generally with a radio-driver abstraction (Meshtastic as the first driver, SDR as a co-equal pillar, room for wider LoRa and multi-transport backhaul); north-star vision of a self-adapting, multi-transport, cockroach-resilient fabric documented honestly as the destination, not a current claim.

PackageVariant and PackageVariantSet examples plus a Porch registration and propose/approve guide.

### Changed

- The `govulncheck` gate earned its place on its first CI run by catching a reachable vulnerability the local api-only check had missed: an infinite-loop bug in `golang.org/x/text` reachable through the operator's status-update path. Fixed by bumping `golang.org/x/text` and `golang.org/x/net`, then pinning the build toolchain to `go1.26.5` (with the matching CI `go-version`) to clear a reachable `crypto/tls` standard-library advisory. Both modules now scan clean under `govulncheck` with zero reachable vulnerabilities.
- Maintenance pass on the operator after an adversarial two-checker review, all findings fixed with regression tests: the config diff now compares values case-sensitively (case folding was hiding real drift in fields like an MQTT root topic); a bounded apply-and-reboot loop (`status.applyAttempts`, `Degraded` condition after `MaxApplyAttempts`) prevents an unconvergeable field from rebooting a device forever; the never-populated `firmwareVersion`/`neighborCount` status fields were dropped until parsed on hardware; and an unexpected reboot error is surfaced rather than swallowed.
- Operator security hardening from the same review: the unused cluster-wide Secret RBAC grant was removed (least privilege; it plus the pod token was a cluster-exfiltration path), the `connection.tcp.host` field gained a shape pattern and length bound (SSRF and flag-injection surface), the operator package gained an egress NetworkPolicy and a read-only root filesystem with a `/tmp` emptyDir, and a unit test asserts the config builder can never emit a transmit-power key. The threat model clarifies that a Meshtastic mesh node transmits by design on ISM (distinct from the SDR receive-only interlock) and that region changes stay human-approved.
- Legality notes across the docs are now uniformly hedged, US-scoped, marked as informal non-lawyer research, and linked to the disclaimer. No document asserts legality as settled fact.
- Phase 0 close-out: the open decisions in the plan docs are resolved with evidence (GitHub owner, `deletionPolicy` enum over a boolean, secrets story, SPDX and DCO and lib direction); explicit code-quality bars and cross-platform rules added to `AGENTS.md`. The `nephmesh.io` API group is a provisional placeholder (no domain owned; renaming stays cheap at v1alpha1) and revisited only before a public or 1.0 release.
- Recorded the Meshtasticator attempt: multi-node simulation is not practical headless in containers today, so CI stays single-node; revisit paths noted.
