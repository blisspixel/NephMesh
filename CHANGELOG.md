## [Unreleased]

### Added

- Example `MeshtasticNode` resources (`examples/`): a basic node and a secure-private-channel node with its Secret, plus a README, so a newcomer has a starting point (there were none). The `MeshtasticNode` printer columns gained Preset and LastHeard, so `kubectl get` shows readiness, region, preset, node id, and last-heard at a glance. And the CI integration test now reconciles an MQTT password to `Ready` against `meshtasticd --sim`, locking the write-only-password convergence fix on real firmware, the exact bug the in-memory fake had hidden.

- A reproducible operator demo (`demo/operator/`), the hardware-free, $0 way for a stranger to watch the flagship work: it stands up a simulated Meshtastic radio (real firmware, no RF) and runs the operator's real reconcile loop to converge it to a declared intent, including a secure private channel, drift detected, only the change applied, reboot, re-verify to `Ready`, the channel confirmed by key-hash match, then proves idempotence on a second run that writes nothing. `reconcile-demo` gained `-channel-name`, `-channel-key`, `-applier`, and `-bin` flags so it can drive and demonstrate the channel path. This is a step toward the 1.0 reproducibility gate and the review's ask to make the value visible rather than asserted; the transcript in the demo README is captured from a real run.
- An airtime-budget prediction (`internal/airtime.PredictedChannelUtilizationPercent`), the "predict" control from the airtime plan and the airtime-as-a-commons differentiator in action per node. When a `MeshtasticNode` declares a modem-preset change, the operator predicts what the channel utilization would become at the new preset (scaling the radio's own measured utilization by the two presets' time-on-air ratio) and surfaces an `AirtimeBudget` status condition, False with the before-and-after numbers when the change is predicted to push the channel past the recommended ceiling. It is deliberately advisory: the declared preset is still applied, because hard refusal of an over-budget change is a fleet decision for a Porch validator (which can see the whole channel), not the per-node reconcile (which cannot see the neighbors). Honest about being a prediction, the measured `AirtimeHealthy` condition stays the ground truth. Unit-tested, hardware-free.

### Fixed

- Node identity and airtime telemetry are now sourced from the exporter's reliable local-node view (`getMyNodeInfo`) rather than scanned out of the whole `--info` node database, which on a real multi-node mesh could return a neighbor's id or channel load, so the operator would report and act on another node's airtime. As a bonus this drops a device round-trip per reconcile (identity now rides the export the loop already fetches). The fake falls back to `--info`, so unit tests are unaffected; validated against `meshtasticd --sim`.
- Hardening from the security and silent-failure review lenses. The operator's NetworkPolicy egress rule for the Kubernetes API server had no destination selector, so it matched all destinations (0.0.0.0/0) on 443 and 6443, a compromised operator could have exfiltrated the Secrets it reads to any public endpoint on 443; it is now restricted to private (RFC1918) ranges (the in-cluster API server is private). The transmit-interlock gate (`hack/check-transmit.sh`), the wire that enforces receive-only, missed `hackrf_transfer`'s `-c` continuous-wave transmit mode and did not scan Dockerfiles or compiled-language sources; both are now covered. And CRD validation gained bounds that were missing: `ChannelSpec.name` is capped at the device's ~12-byte limit (an over-long name would otherwise truncate on the device, never round-trip, and park the node Degraded), and the serial device path and viaGateway dest now carry the same leading-dash-forbidding pattern the TCP host already had, closing a latent argument-injection surface before those transports ship.
- An adversarial code-review fan-out (five reviewers over the reconcile/device, config, controller/secret, Python helpers, and airtime/metrics, every finding then verified skeptically) caught eight more real defects, all fixed with regression tests. Two were HIGH and both were masked by the in-memory fake: (1) a node with an MQTT password never converged, `BuildDesired` put the password in the compared config but the device never echoes a secret back, so it read as permanent drift and reboot-looped to Degraded; the drift comparison now excludes write-only keys (`config.ForComparison`) while the apply still writes them. (2) The two maximum-range modem presets (LONG_MODERATE, LONG_SLOW) were modeled at coding rate 4/5 instead of the firmware's 4/8, under-counting the airtime of exactly the presets most likely to saturate a channel by about 26%. The rest: the redacting `secret.Value` leaked through non-string fmt verbs (`%d`, `%x`) that bypass `String()`, closed with a `fmt.Formatter`; serial-only "unreachable" phrases (a missing file, access denied) were treated as transient on a TCP transport too, so a fatal helper misconfiguration would requeue forever without surfacing, now gated on serial; an unreachable `--info` between the export and the identity read could flip status to `Ready` with an empty node id, now treated as an unreachable step; a channel-utilization metric was never cleared when the value went unknown; the fake's `ExportConfig` shared its `channels` slice by reference, weakening test isolation; an unparseable channel index defaulted to slot 0 instead of being skipped; and the Python apply helper could half-configure a device on a bad entry (it now validates and bounds-checks every channel before any write), silently mangle a malformed base64 key (now `validate=True`), and mishandle an IPv6 or non-numeric `host:port` (now parsed robustly). Verified against the full Go suite and by re-running the channel path against `meshtasticd --sim`.
- A polish and bug-hunt pass over the recent work surfaced three real defects, all fixed. First, the airtime-budget prediction was effectively dead: the reconcile loop read the radio's telemetry only in the converged branch, but the prediction needs the measured channel utilization while a preset change is still pending (which is precisely when the config is not converged), so it never had inputs; telemetry is now read once up front and surfaced on every reachable step. Second, two status conditions could linger stale: an `AirtimeBudget` False persisting after the preset change converged, and a `ChannelsInSync` report persisting after channels were removed from a spec; both are now cleared when they no longer apply. Third, the operator demo used a 14-byte channel key that real firmware would reject, corrected to a valid length. Each fix has a regression test.

## [0.2.1] - 2026-08-07

The operator's configuration surface is complete and it is now observable. 0.2.0 shipped the operator core (region, modem preset, role, MQTT, owner); 0.2.1 adds secure channels and their pre-shared keys, the flagship's last configuration surface, reconciled through the loop and validated against `meshtasticd --sim` in CI on every commit; the radio's airtime telemetry surfaced as Prometheus metrics and an `AirtimeHealthy` condition; a no-default-credentials assume-breach gate; and a design doctrine, the first Architecture Decision Records, and a grounded research pass that frame where the project grows next, deliberately behind a rock-solid core. The phase-gated 0.3 and later milestones (Porch, real radios, multi-site) are unchanged.

### Added

- Channels now converge: the operator applies declared channels through the reconcile loop and drives them to `Ready`, completing the flagship's last configuration surface. `Converge` reconciles the scalar config and the channels together (scalar first, since its reboot also settles the device, then channels through their key-bearing path), gates `Ready` on both, and bounds the channel apply by the same attempt limit so an unconvergeable channel degrades rather than reboots forever. The controller resolves each declared channel's key once from its Secret, producing both the compare hash (for drift and the condition) and the write payload (the key wrapped in the redacting type, revealed only when the apply file is written); a channel with no `pskSecretRef` uses the device default, whose hash is the `0x01` shorthand, so a default channel no longer reads as permanent drift. The packaged operator is wired for this end to end: the image bundles the exporter and channel-apply helpers, the TCP device client uses the exporter (which emits the channel set the CLI's `--export-config` omits) and the applier, and the exporter's TCP host:port handling was fixed. Proven end to end against `meshtasticd --sim` (export emits channels, apply writes them, both over TCP) and unit-tested through the fake (apply, reboot, re-verify to converged). The CI integration test now reconciles a Secret-backed secondary channel to `Ready` on every commit, through the same helpers the packaged operator uses, so channel convergence is checked continuously rather than only by hand.
- The device-layer channel apply capability (`device.ApplyChannels`), the mechanism validated against `meshtasticd --sim`. Channels write through a bundled helper (`hack/mesh-apply.py`) that reads the keys from a file, never the command line, so a channel key never appears in a process argument or a log line, the same non-exposure the broker password gets from writing `--configure` to a file. The apply is per-channel through the device library (no fragile `channel_url` encoding, which the sim probe proved unnecessary), the default key is the single `0x01` byte, and the device reboots as with a scalar apply. Keys are carried in the redacting type until the file is written, and the fake models the write (storing the key hashed, then rebooting) so the converging loop can be tested end to end. Unit-tested, including a proof that the key stays out of argv, and validated on the sim. It is wired into the converging reconcile loop (see the channels entry above).
- A Nephio compatibility posture doc (`docs/reference/nephio-compatibility.md`), grounded in a fresh check of the upstream `nephio-project/api` and `nephio-project/nephio` repositories (2026-08-07): where NephMesh already aligns (a separate `api` Go module with domain-suffixed `v1alpha1` groups, controller-runtime operators, Configuration-as-Data with kpt and Porch and `PackageVariant`, and the `CommunicationIntent`-as-KRM direction), where it deliberately diverges (the `mesh.nephmesh.io` group rather than squatting `nephio.org`, and newer Kubernetes libraries than upstream's `api` module carries), and the one thing to watch: interop stays at the KRM and package boundary, which is independent of Go library versions, so the forward version skew costs nothing unless NephMesh ever imports Nephio Go types directly.
- Channel drift now surfaces as an observational `ChannelsInSync` status condition. The controller resolves each declared channel's key from its Secret (the same namespaced, get-only, uncached path the broker password uses, hashed on read so the key never leaves the resolver), the Converge step surfaces the device's live channels from the export it already fetched (no second read of the single-client device), and the controller reports True when every declared channel matches or False with the drifted field paths (the field, never the key). It stays observability, not a gate: channels apply through a distinct path, so detecting drift is decoupled from acting on it, and a node that declares no channels carries no condition at all. A declared channel whose PSK Secret is missing is surfaced as an error rather than silently ignored. Unit-tested through the fake device and a fake-client reconcile.
- The first slice of channel and PSK reconcile, the flagship's last configuration surface (`internal/config/channels.go`): the operator can now project a node's declared channels and the device's live channels into a comparable form and report per-channel drift (name, uplink, downlink, and key). Keys are compared by SHA-256 hash, never by value, so a channel key never moves through the diff, the logs, or the status, matching the redacting-secret posture the rest of the operator holds. The bundled exporter (`hack/mesh-export.py`) now emits each configured channel with its key hashed, validated read-only against a physical T-Deck. That validation surfaced the attempt-and-record subtlety the roadmap flagged: the device stores the one-byte default-key shorthand (the primary channel's hash is the SHA-256 of a single 0x01 byte), not the expanded key, so the converging apply (landed as a separate, later slice, kept out of the loop until the normalization was validated to avoid a re-apply-forever loop) normalizes the declared key to the device's representation. The channel projection and diff are pure and unit-tested (the config package holds 97% coverage).
- The same research fan-out applied to the SDR pillar, with a new roadmap "In consideration" section that names the seductive frontier ideas openly, each with what it opens, its honest constraint, and what would unlock it, headlined by SDR transmit. Three cited docs back it: `docs/research/sdr-transmit-considerations.md` (SDR transmit as a gated, authorization-required frontier, with receive-only staying the default posture that CI depends on, framed as possibility-and-boundaries rather than a how-to), `docs/research/spectrum-classification.md` (moving from "the band is busy" to "busy with what, and is it mine", my mesh versus another network versus a jammer, surfaced as evidence for the closed loop and safety kernel, and deliberately skeptical about overstated RF-ML), and `docs/research/situational-awareness-receiver.md` (a containerized, receive-only, multi-band receiver for a disaster "what is on the air around me" picture, with honest reception-legality caveats and a note that the classic NOAA APT weather satellites were decommissioned in 2025). All receive-only or explicitly gated, all $0 and simulation-first.
- A research fan-out over the roadmap's bigger open questions: eight cited design and research docs, each now referenced from the roadmap at the stage where it becomes load-bearing. `docs/plans/communication-intent.md` (the outcome-level CRD and report-only compiler, grounded in RFC 9315), `docs/plans/signed-autonomy-and-safety-kernel.md` (the signed intent capsule, a monotonic degrading lease, the deterministic site steward, and a Simplex-style safety kernel), `docs/plans/rejoin-and-self-stabilization.md` (rejoin as a negotiated treaty, self-stabilization as the formal goal, selective CRDTs), `docs/plans/key-rotation-and-epochs.md` (make-before-break fleet PSK rotation and epoch-keyed channels, stating plainly the revocation limit), `docs/plans/message-auth-envelope.md` (a compact Ed25519 authentication-and-freshness envelope for automation packets with clock-free monotonic freshness), `docs/plans/contingency-semantics-dtn.md` (the MessageIntent envelope, degraded fabric modes, and borrowed BPv7 semantics at gateways), `docs/research/second-radio-driver.md` (a minimal driver contract and a MeshCore/Reticulum/ChirpStack comparison recommending MeshCore first), and `docs/research/sdr-trust-anchor.md` (receive-only claim-vs-air spoof and Sybil detection, skeptical about overstated commodity-SDR LoRa decode). Each is marked design or research direction, not shipped, and grounds its claims in cited primary sources.
- A design doctrine and the first Architecture Decision Records, turning a large body of architectural feedback into durable, humble design artifacts rather than premature code. `docs/design/doctrine.md` works through the core reframe (reconcile a communications fabric toward a bounded set of viable mission outcomes, not individual radios to a fixed configuration), `MeshtasticNode` as the compiled output of a higher-level `CommunicationIntent`, viability over target-state convergence, management-plane dissolution (a signed intent capsule, a degrading lease, selective forgetting), airtime as a governed commons, least-change as a first-class invariant, risk-tiered autonomy, rejoin as a treaty, a vector of coherence metrics, and the honest boundaries (physics caps the useful envelope; the audience is organized-operator resilience; over-scoping is the main failure mode). `docs/adr/` records it as decisions: 0001 (intent as an outcome envelope) and 0002 (define signed autonomy and rejoin before the Phase 6 closed loop), both Proposed. Every claim is marked as design direction, not shipped, and the roadmap gains a "Design direction" section placing the whole frontier explicitly behind a rock-solid core (channels and keys, multi-site, key rotation, reproducible demos). This lands the roadmap's outstanding ADR item.
- An informal per-region regulatory matrix (`docs/reference/regulatory-matrix.md`): band, duty cycle, power, listen-before-talk, and encryption-legality notes for the main Meshtastic regions, clearly caveated as non-lawyer research that defers to the primary sources, and tied to the airtime-commons doctrine (duty cycle is a per-region hard constraint a `ChannelBudget` must respect).
- A Prometheus metrics layer (`internal/metrics`): the operator publishes per-node mesh KPIs, readiness, config-in-sync, apply attempts, and the radio's measured channel utilization and transmit airtime, as gauges on the manager's existing `/metrics` endpoint, and drops a node's series when it is deleted. This is the observability layer the research sweep named the single most important gap, and the substrate for the resilience numbers the roadmap committed to (message delivery, time-to-failover) and for the Phase 6 closed loop. Unit-tested with the Prometheus testutil.
- A no-default-credentials assume-breach gate (`hack/check-secrets.sh`, wired into CI and `make check`): a deployable manifest can never embed the Meshtastic default channel key, the public broker host, or its default account as a value (shipping a default channel key means anyone can read the channel). Comments and docs that name these as facts are excluded; proven against a planted credential.
- An airtime model (`internal/airtime`): LoRa time-on-air (the Semtech formula) and duty-cycle cost per frame for each Meshtastic modem preset, with the preset radio-parameter table, unit-tested against a hand-computed Semtech reference value. Airtime, not node count, is the real LoRa-mesh scaling wall (the top finding of the research sweep, backed by the canonical literature), and governing it as enforced budget is the guarantee only a declarative intent system can offer over hand-tuned configuration; this is that model's foundation.
- The device client now also reads the radio's own airtime telemetry (`airUtilTx`, `channelUtilization`) from `--info`, the ground-truth measurement of channel load noticed in the first real-hardware session, and the operator surfaces it as an `AirtimeHealthy` status condition (False when channel utilization or transmit airtime exceeds the recommended ceilings, a busy-channel heuristic and the conservative EU 10% duty cycle), so a saturating channel is visible rather than silently degrading. `docs/plans/airtime-budget.md` designs the enforced budget on top of both halves: predict a config change's cost with the model, observe actual load with this telemetry, and reject a fleet change that oversubscribes a channel via a Porch validator at Phase 5. The `reconcile-demo` observe mode reports both the predicted and measured airtime.
- USB serial transport for the operator's device client, and the first real-hardware validation of the full reconcile loop against a physical Meshtastic T-Deck (firmware 2.7.26, node `!0c3a5f2c`). The operator's own `Converge` loop drove the real board over USB: it read the config, detected an owner drift, applied it over serial, the device rebooted, and it re-verified to `Ready` and restored the original owner, the core of the 0.4 gate (the operator reconciling drift on real hardware). Real-hardware testing surfaced two findings, both handled: the CLI's `--export-config` hangs over serial (it re-requests config over admin messages that time out on the device, while `--info` and the connect-streamed config are reliable), so the client uses a bundled exporter (`hack/mesh-export.py`) that reads the streamed config and emits the operator's export format over both serial and TCP; and a device drops off the USB bus while rebooting, so the client now treats a briefly-unopenable serial port as transient unreachable (requeue) rather than a hard failure. The `reconcile-demo` tool gained `-serial`, `-exporter`, a read-only `-observe` mode, and owner/region/preset intent flags, all unit-tested.
- A resilient-comms landscape synthesis (`docs/research/resilient-comms-landscape.md`) from a five-stream research sweep (disruption-tolerant comms, intent-based networking, adversarial mesh security, LoRa prior art, adjacent off-grid ecosystems), with a ranked research-informed backlog, consolidated sources, and honest myth-busts (single-digit-km real range, no LoRa anti-jam security, the satellite-market shakeout, and that a HackRF can actually decode LoRa). The two highest-confidence findings: airtime is the real scaling wall (so an enforced airtime-budget invariant is the clearest differentiator), and the multi-driver seam is validatable now via MeshCore or ChirpStack.

### Changed

- Framing corrections the sweep surfaced, so the docs do not overclaim: the README security paragraph now states that a shared channel key gives confidentiality but not per-sender authentication and links the threat model; the novelty claim names Reticulum as the closest philosophical neighbor (a candidate managed driver, not a competitor) rather than implying a green field; the "no Meshtastic operator exists" claim carries a last-verified date; and any ATAK interop is scoped to compressed TAKPacket on-mesh, CoT at the gateway. The threat model gains an untrusted-RF-medium boundary with two testable controls (an application-layer auth-and-freshness envelope, and the receive-only SDR as an out-of-band trust anchor), and the roadmap carries the ranked research backlog.

## [0.2.0] - 2026-08-05

The `MeshtasticNode` operator milestone, all hardware-free. The flagship operator reconciles a Meshtastic node's configuration (region, modem preset, role, MQTT with a broker password read from a Secret, and owner) against a live `meshtasticd --sim` in CI, ships as a kpt package, and is hardened with an envtest controller tier, assume-breach control-proving tests, a supply-chain pass, and a redacting-secret path. The version path was revised so this software milestone earns its own release rather than waiting on hardware (see `docs/roadmap.md`).

### Added

- Secret handling for the operator's secure-comms surface: the MQTT broker password is now read from a Kubernetes Secret and written into the device's MQTT module config, alongside the username. The value is wrapped in a redacting type (`internal/secret`) whose every render path (fmt verbs, JSON, the logr hook) shows a placeholder, so it cannot leak through a log line or error; only an explicit reveal at the config-write point returns the bytes. A no-secret-in-logs assume-breach test drives a sentinel password through a full reconcile and proves it reaches the device but never a log or the stored status. The Secret is read uncached with a namespaced `Role` granting `get` only (never a cluster-wide grant, so a compromised token cannot read Secrets fleet-wide), enforced by the RBAC golden test. Channel PSKs will follow the same path once the `channel_url` apply is built.
- A `cmd/reconcile-demo` tool that runs the operator's real reconcile loop (the `Converge` state machine and CLI-backed device client the controller uses) against a live `meshtasticd`, sim or hardware, and prints each step's outcome, so the convergence can be watched without a cluster. It surfaced a real quirk in the process: a field left at the device default (for example the `LONG_FAST` modem preset) reads as permanent drift because Meshtastic's export omits defaults, so the tool declares a non-default value.
- Terminal captures under `docs/media/` (rendered from real runs): NephMesh's reconcile loop converging a live `meshtasticd --sim` (via `reconcile-demo`) in the README, the assume-breach admission suite refusing six hostile custom resources in the threat model, and the quality gates plus coverage in the standards doc. Bare `make` now shows the documented target list instead of silently running a gate.
- envtest controller tier (`internal/controller/envtest_test.go`, build-tagged, in a dedicated CI job): the reconciler and CRD are exercised against a real API server and etcd, which the fake client cannot reproduce. It proves the assume-breach admission control (six hostile mutations of a valid `MeshtasticNode`, a leading-dash host, an out-of-range port, two transports at once, a bad region, an over-long owner short name, are each refused with an Invalid error, and the valid resource is accepted) plus the finalizer lifecycle and reconciler idempotency (a converged node is not re-applied). Validated against a real control plane before landing.
- The operator now reconciles the node `owner` (long and short name), emitted as the top-level `owner`/`owner_short` scalars the export uses and verified to round-trip through `--configure` against `meshtasticd --sim`. Channels remain unimplemented because the export encodes them as a single `channel_url`, not discrete fields.
- First assume-breach control-proving test: a golden test (`internal/controller/rbac_policy_test.go`) reads the operator's actual shipped ClusterRole and asserts it equals a least-privilege allowlist, failing the build on any extra grant, a Secret rule, a wildcard, or an escalation verb. It guards the earlier removal of the cluster-wide Secret grant against silent regression and is proven to fail against a planted grant.
- Supply-chain hardening for CI: every GitHub Action is pinned to an immutable commit SHA (with the human-readable version in a trailing comment) instead of a mutable tag like `@v4`, closing the hole where a moved or compromised tag would run arbitrary code with the workflow token. A deterministic gate (`hack/check-actions.sh`, `make check-actions`) fails the build if any action is ever left on a tag or a workflow omits a top-level `permissions` block. The kpt install in CI now downloads to a file and verifies its SHA-256 against the release checksum before extracting, instead of piping `curl` straight into `sudo tar`. Both workflows declare a least-privilege top-level `permissions: contents: read`.
- Dependabot (`.github/dependabot.yml`) keeps Go modules, GitHub Actions, and Docker base images current, grouped so a week's minor and patch bumps arrive as one reviewable PR per ecosystem and every update runs the full gates before it can land. Kubernetes library minor and major bumps are ignored (they force the go directive forward and need a tested migration); their patches still flow.
- A `docs/CODE-QUALITY-STANDARDS.md` synthesizing August-2026 research into exceptional Go, shell, Docker, and operator engineering plus assume-breach testing, with an honest enforced-versus-gap breakdown and an explicit overkill list. First wave of gates wired: native fuzzing of the untrusted device-output parsers (proven to run clean), the Go race detector and `govulncheck` in CI, and ShellCheck on the gate scripts. Fixed a real bug it surfaced: the operator's logger defaulted to development mode in the released binary.
- A research-backed plan for agentic AI nodes on the mesh (`docs/plans/agent-mesh-nodes.md`): an offline, retrieval-grounded, advice-only AI node reachable over LoRa when the internet is gone. It leads with the hard constraints (a ~200-byte telegram budget, a template-and-code message scheme, the model at a powered base with cheap field radios, air-gapped from all transmit and config paths, human-decides), is global by construction (region and encryption as configuration, not US assumptions), and honestly separates the real disruption-tolerant and DTN parallels from the space hype. Architecture and roadmap updated with global-by-configuration and disruption-tolerant design principles.
- The operator now reconciles modem preset and device role in addition to region and MQTT. Each new field's export path was verified to round-trip against `meshtasticd --sim` in the integration test, so an unconvergeable field cannot slip in.
- A tool-agnostic agentic layer so any coding agent (Claude Code, Codex, Copilot) or a human can drive the repo the same way: `docs/agent-playbook.md` documents the canonical commands and the layering (AGENTS.md for conventions, the playbook for commands, a future MCP server for live state, chosen over an assistant-specific skill format for portability), and `hack/check-all.sh` runs every gate in one command, gracefully skipping a group whose tooling is absent. Exposed as `make check-all`.
- Operator integration test against real firmware: a build-tagged test drives the real reconcile loop, through the CLI-backed device client, against a live `meshtasticd --sim`, reaching convergence and reporting the real node id. It runs in a CI job (a Docker sim device plus the pinned CLI) and passes locally in about 10 seconds, giving the flagship operator an "executed against real firmware" validation that the in-memory fake cannot.
- Deterministic Go quality gates in CI, per the anti-slop mandate that wired gates beat instructions: golangci-lint (shared `.golangci.yml`, standard linter set, generated files excluded) and a meaningful-coverage floor (`hack/check-coverage.sh`, 80%, excluding generated deepcopy and the thin cmd/main), both wired into the `go` workflow for the api and operator modules and exposed as Makefile targets. The coverage gate is proven to fail below threshold. Fixed the lint findings it surfaced (unchecked errors, a deprecated field).

Renders clean through the gate, correctly keeping the CRD and ClusterRole cluster-scoped while namespacing the ServiceAccount and Deployment.

A pure `Converge` state machine (export, diff, apply-and-reboot on drift, report RebootPending and a requeue delay, re-verify after the device returns) drives status conditions (Reachable, ConfigInSync, RebootPending, Ready). The device sits behind a `Client` interface with a deterministic in-memory fake, a CLI-backed implementation that execs the Meshtastic CLI, and a graceful "unsupported" stand-in for transports not yet built. The whole operator is unit-tested hardware-free and cluster-free using the fake device and controller-runtime's fake client (config and reconcile at 100%, controller 85%, device 83%); a `go` CI job builds, vets, and tests it.

A `connection` oneof (tcp/serial/viaGateway) enforced by a CEL rule so no validating webhook is needed, open-string enums for firmware-churn tolerance, channel PSKs by `secretKeyRef` only, a `deletionPolicy` enum, and standard status conditions. Generated deepcopy and CRD manifest via pinned controller-gen; testify unit tests (hand-written logic at 100% coverage); a `go` CI workflow running build, vet, test, and a generated-artifact freshness check.

### Changed

- The `govulncheck` gate earned its place on its first CI run by catching a reachable vulnerability the local api-only check had missed: an infinite-loop bug in `golang.org/x/text` reachable through the operator's status-update path. Fixed by bumping `golang.org/x/text` and `golang.org/x/net`, then pinning the CI `go-version` to `1.25.12`, the current 1.25-line patch that carries the backported `crypto/tls` fix for a second reachable advisory. Staying on the 1.25 line keeps the prebuilt golangci-lint (bumped here to the latest GA, `v2.12.2`) compatible with the toolchain that loads the packages, while still building, testing, and scanning under a fully patched standard library. Both modules now scan clean under `govulncheck` with zero reachable vulnerabilities. Dependencies stay minimal and current.
- Maintenance pass on the operator after an adversarial two-checker review, all findings fixed with regression tests: the config diff now compares values case-sensitively (case folding was hiding real drift in fields like an MQTT root topic); a bounded apply-and-reboot loop (`status.applyAttempts`, `Degraded` condition after `MaxApplyAttempts`) prevents an unconvergeable field from rebooting a device forever; the never-populated `firmwareVersion`/`neighborCount` status fields were dropped until parsed on hardware; and an unexpected reboot error is surfaced rather than swallowed.
